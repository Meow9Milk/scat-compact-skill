# SCAT分析のコンパクト化

既存の分析表・発言資料・指定された参考例を読み、根拠を追える簡潔な分析表を作る。

## 整理の手順

1. 発言番号、発話者、テクスト、各コード、ストーリーラインを確認する。セルのメモにある要約前のテクストも確認する。
2. 分析問いに照らし、重複する主張を論点ごとにまとめる。発話者間の対立、判断留保、条件、推測は残す。論点数は内容に合わせ、7件などに固定しない。
3. ストーリーラインと表の論点の順序を対応させる。背景、選択肢、実務上の課題、対応策、到達点など、対象に合う順序を選ぶ。順序変更によって未確認の因果関係を作らない。
4. 統合した論点を次の列で整理する。
   - 論点番号
   - 発話者と元の発言番号
   - テクストの統合要約
   - 〈1〉代表的な原文の抜粋と発言番号
   - 〈2〉簡潔な言い換え
   - 〈3〉内容を説明するテクスト外の概念
   - 〈4〉テーマ・構成概念
   - 〈5〉残る疑問・課題
5. 〈4〉の関係を短いストーリーラインにする。理論記述を含める場合は、本事例からの暫定的命題として簡潔に記す。表と文章で同じ説明を繰り返しすぎない。
6. 元の発言を確認用シートに保持し、主表から元番号でたどれるようにする。統合表は原発言単位の分析表とは区別する。除外した論点があれば理由を説明する。

## 根拠と表現

- 〈1〉は原文に一致する抜粋にする。要約を原文引用として扱わない。原文がないときは確認できない範囲を明示する。
- 「少ない」と「ない」、「検討中」と「決定済み」、発言者の認識と確認された事実を区別する。
- 統合しても異なる発言者が一致しているように書き換えない。
- 発言時点の議論を現在の制度や法律の説明として扱わない。
- 参考例は分析の粒度や構成に用い、その事例固有の結論を移植しない。

## Excelの確認

実行環境で利用できる表計算の作成・検証手段を使う。原資料を上書きせず、別名で保存する。抜粋と元番号の一致、統合前後の論点の対応、原資料・メモの保持を確認する。見出し・折り返し・行高を調整し、文字が切れていないことを確認して、完成したExcelを渡す。
